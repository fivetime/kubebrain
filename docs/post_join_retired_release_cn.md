# 可信退任协议：先完成本任期清理，再做精确条件释放

## 问题与边界

[上轮实验与路径复现](peer_fault_da303fdb_20260918_cn.md) 已确认：client-go
v0.36.2 的普通释放路径会在生命周期清理前，用独立 RenewDeadline 上下文
读取后端。后端隔离时，可信 peer 的退任通知可能因此等待。受控测试证明
该顺序同时存在于正常退出和续约失败；尚不能推断现场实际等待时长。

## 修复

只有显式调用 `NewLeaderElectionWithRetirement`、安装了回调、后端同时
提供 `OwnershipConditionProvider` 和带非空 scope 的
`RetiredOwnershipReleaser` 时启用新路径。普通构造器、无回调、无 scope
或无快照能力均保留原 client-go 行为，协议仍默认关闭。

新路径不调用 client-go 的提前释放读取。退出 elector 后，先不可逆地
终止旧任期新鲜度，等待初始化回调退出并完成既有清理；这些边界没有删除。
随后读取本任期已冻结的凭据，尝试一次本地精确条件释放，其上下文预算为
一个原有 RetryPeriod（现场配置为 500 ms），不额外等待完整的 25 秒
RenewDeadline。此处依赖后端遵守上下文取消，不用遗留后台写入来伪造超时。

本地尝试使用既有 scope、旧 record 和旧 fence token 的原子 CAS；不能
以“当前 holder 名称相同”为依据重新取得凭据。无论成功、失败或提交结果
不确定，随后 peer 回调得到的仍是同一份冻结条件。若另一个任期已取得
同名 holder，旧条件必须冲突，不能清除新锁。若没有精确凭据，则不做本地
条件释放，并向回调传递 available=false，保留租约自然过期的安全退路。

正常退出仍做这一短时本地尝试；peer 回调继续收到原来的已取消上下文，
不能借修复向关机后的远端发送请求。既有退出确认逻辑未删除。LeaseDuration、
RenewDeadline、RetryPeriod 配置和原 30 秒验收门限均未修改。

## 本地验证与未完成项

- 选主包 race 回归通过（3.876 秒）；之后选主包与后端选主包再次通过
  （4.100 / 2.019 秒），选主包 `go vet` 通过。
- `pkg/server` 中 `TestPeerRetirement|TestRetirement` 的 race 回归通过
  （35.629 秒），包含真实网络交接和存储故障下的原续租流。
- 成功、超时、不确定提交、同名新任期、缺失凭据五类场景重复 20 次通过
  （24.519 秒）。补充正常退出及构造器启用条件后重复通过（25.174 秒）；
  进一步断言新任期确实提交后，最终 20 次重复通过（25.136 秒）。
- 提交 `534d3cbf` 的完整扩展回归
  `go test -race -count=1 -timeout=15m ./pkg/server ./pkg/server/service/leader ./pkg/backend/election`
  通过（45.832 / 4.142 / 2.100 秒），不是只选取退任用例。三个包的
  `go vet` 全部通过。日志、退出码和源码摘要保存在本机私有目录
  `/root/.local/state/kubebrain/post-join-release.IMrV5aGw/`。
- 随后将真实网络原流测试的任期断言从“不低于旧任期”加强为“不低于
  已确认的后继任期”，并在路由提示过期、重新验证后的每次续租上保持此
  断言。三个网络交接测试 race 通过（34.801 秒），原入口后端始终不可用，
  不需要恢复旧入口存储访问才完成续租。此结果不替代真实集群 30 秒门限。

测试中使用真实内存事务/CAS 与受控超时，不等于真实 TiKV 分区验收。
当前在跑的 785fb973 CI 只包含响应任期修复，**不包含本修复**。本修复仍需
独立的对应源码 CI、镜像校验及专用集群原门限实验；不能用上一镜像的成功
状态替代。运行中的 CI 不因本地提交而被取消，本轮不部署新版本。
