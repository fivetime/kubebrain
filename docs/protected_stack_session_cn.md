# 受保护采栈会话工具

`hack/production/protected-stack-session.sh` 将此前实验目录中的会话逻辑
纳入版本管理，并接入 `same-pod-process.jq`。Ready/启动探针标志不再
用作进程身份；Pod UID、完整 spec、IP、容器 ID/镜像标识、重启次数
和启动时间仍必须相同。这不改变产品代码，也不重写既有失败实验。

## 调用约定

仅在新实验 owner、已完成诊断部署后使用。控制器先启用
`set -euo pipefail`、`umask 077`，在同一拥有子进程的 Bash 中 source
该文件，并设置以下变量，不能在命令替换/子 shell 中调用会话函数：

- `stack_owner`：私有证据目录；要求 `deployment-claimed` 存在、`HOLD`
  和 `final-exit-code` 不存在。调用者仍负责新 owner 的单次消费约束。
- `stack_kubeconfig`、`stack_context`：明确的目标集群，不使用隐式上下文。
- `stack_namespace`、`stack_namespace_uid`、`stack_sts`、`stack_sts_uid`：
  本轮重新核验的资源身份。
- `stack_tls`：包含 `ca.crt`、`probe.crt`、`probe.key` 的私有目录。
- `stack_server_name`：info 服务 TLS 名称。
- `stack_info_port`、`stack_anonymous_port`：可选显式本地端口，默认
  18584/18585；必须是两个不同的 1024–65535 十进制端口，不接受前导零。
  在 prepare 前设置，准备后 capture/rearm 拒绝端口漂移。并行指标采样
  可在独立控制器 shell 中使用 18586/18587；仍需提前检查空闲端口。

owner 下准备 `diagnostic-spec.json`（完整 StatefulSet spec）、`info.crt`
（预先核验的服务端证书）及 `bin/info-diagnostic-probe`。固定工具目录
应同时包含库文件和 jq 身份规则。`tools.sha256` 必须覆盖这两个文件
及探针，`diagnostic-inputs.sha256` 必须覆盖 spec 和证书；路径使用
对应实际绝对路径。清单完整覆盖和摘要均在 prepare/capture 时检查。
清单自身的可信来源、源码/镜像绑定由外层实验准入验证，不能靠重新
计算清单将未知修改视为已审核。

外层控制器必须安装 EXIT 清理 `stack_session_close`，TERM/INT 分别
退出 143/130，并负责其余故障资源的恢复。调用顺序：

1. `stack_session_prepare <StatefulSet名称-序号>`，预先建立两个指向
   精确 Pod 的 localhost info 转发，固定本会话选择的端口对。
2. `stack_session_capture before-fault`，输出目录由 `stack_capture` 返回。
3. 故障激活前记录原始纳秒起点；所有后续 capture 传同一个起点。
4. 读取采集结果后执行外层原有等待栈/降主栈分类与响应断言，最后恢复。

仅支持单应用容器模板、info 端口 8080。每次采集检查 namespace/STS
身份、诊断配置、采集前后进程身份以及与预热时进程的一致性。TLS
正向鉴权、匿名拒绝、服务端公钥 pin 验证由实际 protected-stack 探针
执行。此库不以 Ready 作为采栈条件，也不替代服务可用性门限。

匿名 TLS 拒绝有时会令对应 kubectl 转发因连接重置退出。故障前每次
成功采栈完成身份检查后，库会停止并 join 旧匿名转发，再向同一个
Pod 名称创建新匿名转发，为下一次采栈预热；日志使用独立文件保留。
只操作本 shell 所拥有的子任务，先确认端口空闲，再等待监听就绪；
端口占用、启动失败或取消均不写此次 `COMPLETE`。正向通道不重建。
此步骤记录为 `rearm-anonymous`，仅允许在尚未设置故障起点时执行。
故障后的采栈不重连、不补充时间预算；任何通道提前失效仍失败。
新通道不代表身份已验证：下一次采栈仍须做完整前后 Pod 身份检查、
SPKI/mTLS 和新的匿名拒绝验证。此前拒绝证据不得替代下一次验证。

独立端口对仅提供并行控制器的基础条件，不代表已实现采样调度器。
现在另提供 `stack_session_capture_metrics_at <原始故障起点ns> <偏移ns>`
作为独立控制器的单次定时入口。须先 prepare 并完成故障前指标采集；
调用者仍负责进程启动、故障起点交付和退出汇合，不是自动部署/实验入口。
偏移为非负整数且小于 30 秒；调用前设置同一个原始起点，等待时每秒或
更短重新核验预算。若已经超过目标偏移但仍在原截止时间内，会立即采集，
实际时间以 probe/timing 记录为准，不伪称准点。过期、未来起点、起点漂移、
重复安排、等待或采集失败都不会生成调度成功标记，也不重试或重连。

`metrics-schedule.*` 中的 input.tsv 保存起点/偏移；成功时 capture-path
指向已完成的 metrics 目录，evidence.sha256 绑定两者及采集摘要清单。
只有最终预算检查成功才写 COMPLETE；它明确不是 fault acceptance。
多个时间点必须使用分别准备且持有不同端口的控制器，不能在故障中重新
准备已断开的匿名转发来补采样。并行实验的外层编排仍待接入和验证。
每个控制器必须自己 prepare 并拥有/清理子进程，不能把已准备会话直接
放入后台 subshell 复用 job 表。外层仍须固定同一故障起点、绑定工具和
资源身份、等待指标采集终态后再恢复/替换目标 Pod，并保留原验收条件。

## 独立 metrics worker 入口

`protected-metrics-worker.sh <Pod名称> <偏移ns>` 必须在新的受监护 Bash
进程运行。将上述 stack_* 配置作为环境传入，owner 必须为不含换行/tab
的绝对私有路径；默认独立端口为 18586/18587。worker 脚本本身也必须
纳入已审核的 tools.sha256。不要在已准备转发的 shell 中直接后台复用。

控制协议为 stdout 的制表符分隔单行和 stdin 的一个十进制故障起点：

1. worker 完成 prepare 和故障前 metrics capture 后输出
   `READY<TAB>worker目录<TAB>基线目录`。此前任何失败都不输出 READY。
2. 外层确认所有必要基线和工作进程就绪后，按原规则激活故障，并向
   stdin 写入同一个原始故障起点 ns 加换行。worker 最多等待 60 秒，
   每秒复查 owner，跨超时分片保留已读字符但不重置总期限；读取结束时
   也检查总期限。控制记录最多读 20 字符；EOF、非法输入或超时均失败，
   不执行 shell 输入。等待中 HOLD/终态不需要收到新输入即可触发退出。
3. 单次定时采集成功后输出 `CAPTURED<TAB>采集目录<TAB>调度目录`。
   外层必须继续检查进程退出码及原有证据，不能仅看到该行就开始恢复。
4. EXIT/TERM/INT 清理本 worker 持有的转发，worker 目录保存 exit-code。
   stderr 应由外层写入私有日志。超时或强杀可能没有退出记录，不能当成功。

此入口不执行故障注入、集群恢复或多 worker 编排。外层仍须负责进程组
取消、等待所有进程结束后再恢复。控制协议测试使用合成库；另有真实
会话库集成测试（Kubernetes/探针仍为夹具），验证基线与采集目录能被
离线核验器读取、差值及调度清单正确、退出后转发进程均消失。真实集群
上的整合及多个进程同时运行尚未验证。

## 原时间预算与失败处理

故障后总预算始终为原起点加 30 秒；单个外部操作上限 25 秒且受剩余
预算限制。禁止重新传入 before-fault 或更换起点。控制器必须继续用
原截止时间限制整个故障流程，不把探针完成标记当作全流程验收通过。

同步命令使用 foreground timeout，外层控制器应由可取消整个进程组的
监护进程运行。关闭只处理当前 shell 拥有的后台任务，避免对陈旧 PID
误发信号。任何失败都不得继续执行成功断言。完整采集及最后期限检查
通过后才写 `COMPLETE`；部分目录保留作为失败证据。

owner 有效性不仅在 prepare 时检查：capture、匿名通道重建、定时等待
各轮以及最终写完成标记前，都要求 deployment-claimed 仍存在且 HOLD/
final-exit-code 不存在。准备后终止的 owner 不得继续输出成功采集，终止
发生在探针内时可能留下原始文件，但不会获得 COMPLETE。此检查不能
替代外层的进程取消/汇合：恢复控制器仍必须先停止并等待采集控制器退出。

计时依赖 Bash 5 的 `EPOCHREALTIME`。每个新采集目录另存
`timing.tsv`：Unix 秒（微秒精度）、阶段名、
`start/end`、退出码（start 为 `-`）。阶段覆盖输入摘要验证、采集前
资源快照、前后进程身份检查、受保护探针及采集后 Pod 快照。只记录
阶段名，不记录命令参数、凭据或响应正文。成功采集的摘要清单包含
计时文件；失败/外层取消可能仅留下 start，没有 end，不得据此推断
命令成功或准确完成时间。该墙钟计时仅供定位耗时，不能替代原故障
起点、扩大预算或证明故障验收通过。已有冻结实验不回填此证据。

探针 CLI 还向私有 `probe.stderr` 写入逐行 JSON 请求计时，scope 为
`info_probe_request_timing`。每条只含固定阶段名、start/end、结果分类
和以 Go 单调时钟测得的相对 `elapsed_ns`；不写 URL、证书路径、
凭据、响应体或原始错误。阶段区分已鉴权 ping/ready、匿名 profile
请求和已鉴权 profile 请求。匿名阶段的 `request_error` 可以是预期
TLS 拒绝，只有后续原有证据验证才能证明拒绝；不能单凭计时分类判断
鉴权安全。计时写入失败也会中止采集，不能因同时出现预期 TLS 拒绝
而忽略写入失败。进程被强制终止时可能缺少 end；成功采集的摘要清单
包含 `probe.stderr`。CLI 最后一行仍可能是普通错误信息，应按行区分。
HTTP/1、禁用连接复用/压缩、独立匿名通道、请求顺序及超时保持原样。

## 同一身份约束下的指标捕获

新增 `stack_session_capture_metrics before-fault` 或
`stack_session_capture_metrics "$fault_start_ns"`。仍需原有 prepare、
完整冻结输入及调用方 EXIT/TERM/INT 清理约束；不是独立可直接执行
的采集脚本。输出在新的 `metrics.*` 目录，路径仍由 `stack_capture`
返回。使用 `protected-metrics` 探针保存 `metrics.txt`，不输出栈文件。

复用原 namespace/StatefulSet/spec/Pod 进程校验及前后同进程比较，
不要求 Ready；任何身份漂移拒绝生成 COMPLETE。要求探针退出成功，
摘要模式及所有证明边界正确，文本语法验证为 true，语义证明为 false；
同时验证非符号链接原始文件、非空且不超过 8 MiB 的长度及实际
SHA-256 与摘要相符。文件、摘要、身份和时序
统一写入 evidence.sha256。COMPLETE 仍仅代表本次采集完整，不是指标
语义、业务可用性或整个故障验收通过。

故障起点沿用同一不可重置 30 秒预算；故障前成功采集后可重建匿名
通道，故障中不能重建或延长预算。不能用指标替换必需的降级等待栈
断言，也不能在已经接近截止时追加采集再扩大门限。持续采样调度和
目标 family/同进程差值分析仍待实现，未部署到真实集群。

新指标模式 21 项模拟用例与原栈流程一起 race 通过（28.791s），覆盖
Ready 改变但进程不变、进程重启、namespace/STS/spec 漂移、超时、
时钟重置拒绝、绑定缺失/篡改及原始文件哈希/长度不符。vet、Bash
语法和 diff-check 通过；模拟测试不代替探针的真实 TLS 测试或集群验收。

### 输入校验也受剩余故障预算约束

输入 manifest 的 sha256sum 和精确绑定匹配现在通过
`stack_session_run` 执行，每次使用原故障起点的剩余时间，结束后再
检查截止时间。不会因校验阻塞而继续进入后续探针，也不删减校验。
这用于严格拒绝超预算采集，不是缩短故障恢复延迟的修复。

新增阻塞哈希回归，模拟只剩一秒的故障预算，要求返回 124 且测试
进程在六秒外部安全界限内退出。初版完整回归失败：模拟器错误地在
任何 timeout 包裹命令成功时关闭匿名通道，且慢探针用例的一秒余量
不足以到达探针。已限制模拟器只在探针成功后关闭通道；慢探针用例
从 fault+28s 开始，仍要求原 fault+30s 截止及探针返回 124。

一次尝试把校验合并为子 shell 的方案被阻塞测试发现会遗留子进程，
已撤销，并精确结束其测试 sleep。最终实现直接约束各外部命令，不
保留该子 shell 方案。此前失败会话 65158、70444 不计为通过。
最终旧栈、新指标和阻塞哈希组合 race 通过（会话 16331，100.212s），
vet、Bash 语法与 diff-check 通过。未改集群，未追溯改变故障验收失败。

### 父进程协议读取边界

`internal/metricsworker.Protocol` 为后续协调器提供有界、单消费者的
消息读取：仅允许 READY → CAPTURED → EOF，一行最多 8192 字节，
拒绝不完整消息、额外字段、重复/乱序消息和完成后的额外输出。
路径必须符合当前脚本生成的类型及八位随机后缀，且是指定 owner 的
规范化直接子路径；前后 capture 不能复用同一路径。任一协议错误
永久使该读取器失效，不能略过坏消息继续接受后续消息。

这些是字符串及顺序约束，不证明目录没有符号链接、证据真实性、
worker 成功退出或子进程已回收。协调器仍须独立 LoadCapture 核验
基线后才允许注入故障，绑定同一故障起点及调度证据，完成后等待退出、
核对回执并回收进程。读取等待须由外层取消/超时约束，不能直接无期限
阻塞恢复。当前仅接入实际 worker/会话脚本的模拟集群回归，完整多
worker supervisor 尚未接入真实实验。

`metricsworker.Run` 已提供进程协调核心，调用方必须给出 deadline、
已准入的命令/完整环境、私有 stderr 文件及四个遵守取消的钩子：
worker 的环境始终显式传入；`Env=nil` 与空切片都表示不继承父进程
环境，不能把遗漏配置解释为允许继承认证变量。需要的变量必须由
调用方明确提供（shell 自行设置的内部默认变量不属于父环境继承）。
Baseline（独立核验基线）、Origin（只确定原始起点，不注入故障）、
Inject（接收同一起点并执行故障操作）、Completed（核验采集/调度/
退出回执）。所有基线完成后确定起点，先写入全部 worker 的控制管道，
再且仅再调用一次 Inject；worker 可在 Inject 执行期间采集。管道
写入不等于远端业务或 worker 的采样确认。Inject/Completed 收到的
context deadline 为原始起点加 30 秒与外层 deadline 的较早值，
以便命令适配器从 Deadline() 派生超时时仍使用同一剩余预算；
不能只依赖取消通知却暴露更晚的外层截止时间。Baseline/Origin
仍使用故障前的外层预算，worker 的原始故障计时器保留。不能
在钩子里恢复集群。函数返回前取消进程组并等待直接子进程及读取
协程；失败先向进程组发 TERM，让实际脚本执行 EXIT 清理；5 秒后
仍未退出则升级为 KILL。该宽限仅用于失败后的回收，不延长原始
30 秒采集/故障验收窗口。输入管道直到进程退出并等待完成后才关闭，
避免 EOF 退出清理与 TERM 再入竞争。升级后可能缺少回执，不能判成功。
这不是对逃离进程组的后代或所有 Kubernetes port-forward 残留的
自动证明，恢复前仍须独立清理核验。钩子若不遵守 context，其自身
阻塞无法由该函数安全中断。已接入真实 protected-metrics-worker 与
会话脚本的本机集成测试，覆盖成功采集及基线拒绝；Kubernetes、TLS
通道和探针仍使用模拟器。现已扩展为一个或两个实际 worker 脚本的
联动测试：共享输入仅准备一次，不从已准备 session 的 shell 继承
job table；两个 worker 使用 18586/18587 和 18588/18589，调度偏移
分别为 0 和 100ms。分别核验采集/调度、计数差值及退出回执，并检查
六个模拟转发进程在返回时消失。拒绝场景等所有基线都进入校验后
拒绝最后一个，要求不生成故障起点且两个 worker 均以 143 清理退出。
这证明本机脚本的并发及回收联动，不证明真实端口占用、Kubernetes
故障安装、TLS 传输或真实实验验收；具体实验适配仍未完成。

`metricsworker.RunFaultCommand` 提供 Inject 的外部命令适配：命令必须
由调用方独立准入，使用绝对可执行路径、完整显式环境和私有普通日志
文件。原始 Unix 纳秒时钟作为最后一个独立参数传入，不插值或继承
控制进程环境；stdout/stderr 写入同一日志。缺失/超出原 +30 秒的
deadline、过期/未来时钟、取消或不私有的日志均在启动前拒绝。
命令错误不重试，取消终止进程组并等待直接子进程；返回前也清理仍在
同一进程组的后代。逃离进程组的进程仍须外部核验，不宣称已全部回收。
该脚本必须保留真实隔离、drop、successor、栈和原请求检查，严禁执行
恢复；恢复仍只允许在外层 Run 返回后开始。普通退出码 0 不是这些
检查已覆盖的证明。现有测试只使用本机合成命令，不运行集群故障。

实际 worker/会话脚本联动测试现通过 RunFaultCommand 启动合成外部
回调：回调等待所有 worker 写出调度完成标记才返回，明确覆盖
“采集在 Inject 执行期间推进”，而不是只验证无操作回调。Origin
还独立核验所有基线阶段早于选定起点；回调日志绑定原始纳秒时钟，
外层返回后验证回调 PID 已退出。基线拒绝时回调日志必须为空。
完成标记在这里只用于测试同步，正式验证仍由独立证据读取和原故障
检查负责，不能把标记数量或合成回调成功用作集群验收结论。

### 真实驱动迁移的进程归属约束

2026-09-19 只读核对已退役的 `fault-peer-budget.mjraWKki` 驱动，
确认不能直接将整个 `run-term-experiment.sh` 作为 RunFaultCommand
的命令，也不能简单把故障时间窗内代码剪到一个子 shell：

- 原驱动在故障前启动原始 `lease-term-probe`，随后在同一个 shell
  中 `wait "$probe_pid"` 核验退出。新子 shell 不能等待该进程；
  本机独立复现得到 `not a child of this shell` / 127，而原父 shell
  的 wait 为 0。不能用 `kill -0`、响应文件存在或 PID 消失代替退出码。
- 原驱动的 EXIT trap 调用 `cleanup_term_experiment`，该函数移除
  策略、清除 alarm、撤销租约和停止转发。末尾还显式执行一次网络
  恢复。它们都不能留在 Inject 命令中，否则可能早于指标 worker
  的退出和证据核验解除隔离。
- 原驱动在安装策略前自行生成 `fault_start_ns`。接入后只能接收
  协调器在全部基线通过后广播的同一个时钟，不能再次调用 date
  生成新的故障起点。安装、drop 证据、successor、demoted 栈、原流
  响应及租约/键检查仍须处于原始 30 秒内。

下一步应让同一持有进程负责原始探针的启动和 wait，通过受限协议
与协调器交换准备完成、唯一故障时钟及终态；恢复由外层在所有采集
和故障进程完成回收后执行。必须分别测试准备失败、故障失败、原流
失败、采集失败和取消时的 join-before-restore 顺序。此段是由旧
驱动源码和本机进程实验确认的迁移限制，不是已实现的驱动、恢复
保证或新集群验收；旧 owner 和脚本均保持退役，不可再次执行。

现已增加 `metricsworker.WithPreparedFault` 生命周期适配：独立准入的
同一个脚本先准备并输出严格的 `FAULT_READY` 行；回调内运行采集
协调器，其 Inject 向该脚本 stdin 写入唯一原始时钟。脚本在同一
shell 中等待自己启动的原探针，完成原始检查后输出带相同时钟的
`FAULT_DONE` 行并退出。协议输出限长，缺失/错时钟/额外内容拒绝；
仅 exit 0 不够。环境显式隔离，stderr 只写私有普通文件。
外层回调必须同步调用 Inject、遵守 context，不能自行恢复；重复
注入或回调忽略注入错误也不能判成功。预算验证与 RunFaultCommand
共用原起点 +30 秒上界。返回前取消进程组、等待直接子进程和读取
协程，外部才可进入恢复。逃离进程组的后代仍须另行检查。

此适配不是旧脚本的自动转换器。正式脚本必须移除内部恢复，外层
必须在任何准备阶段变更前持久化恢复所需身份并取得恢复职责，不能
依赖子 shell 的内存变量传回 mutation-attempt 标志。目前只有本机
合成脚本与采集协调器的组合回归；真实故障脚本、部署准入和独立
恢复流程尚未接入，不据此宣称原故障验收通过。

本机实际 worker/会话脚本回归已同时覆盖即时外部命令和准备握手两种
适配，每种均运行单/双 worker 与基线接受/拒绝组合。握手脚本保留
准备阶段启动的合成子进程，在收到故障时钟后由同一 shell wait，
记录退出码 0；依旧要求所有采集在 Inject 返回前完成，并保留原始
基线/调度/差值/回执及转发进程消失检查。基线拒绝时不发送时钟、
不运行故障检查，已准备脚本由外层回收。这里的原始子进程是 sleep，
不是 Kubernetes RPC；测试不证明真实故障或后端恢复。

协调器现在要求启动前已有 `deployment-claimed` 目录，绑定 owner 与
该目录的文件身份，拒绝符号链接目录。启动前、各基线验证后、注入
前后、完成证据验证后及最终返回前复查，同时每 100ms 观察一次并
取消 context。`HOLD` / `final-exit-code` 的任意目录项（包括悬空
符号链接）、查找错误、owner/claim 被替换均阻止继续。遵守 context
的阻塞钩子也会被通知取消。恢复仍须由拥有生命周期互斥权的外层
驱动执行：这些观察不能消除检查与外部恢复之间的 TOCTOU 窗口，
更不能撤回已经由 Inject 钩子执行的故障操作。

完成钩子可使用 `retirementmetrics.LoadScheduledCapture`：输入必须是
独立冻结的 origin/offset、准入身份以及协议解析出的 schedule/capture
目录。函数要求同一父目录，逐字核对 input.tsv、capture-path、固定
完成标记，以及精确三项 SHA-256 清单；不会按清单中的任意路径读文件。
证据文件限长且须是普通文件，拒绝符号链接、FIFO 和设备。

它继续调用 LoadCapture 核验对象/进程/采集证据，并检查采集阶段起点
和探针起点不早于预定偏移、阶段终点和探针完成早于原故障 +30 秒，
拒绝故障期重建匿名通道。阶段时间只有微秒精度：下界按微秒截断比较，
上界保守加一微秒。哈希一致不等于来源认证；这些时间约束不独立证明
清单写完的时刻，不替代可信脚本的最终预算检查、退出回执、外层实验
门限或恢复前进程清理。当前已在模拟集群的真实脚本集成中使用该接口。

## 源码绑定的等待栈采集

`stack_session_capture_expired_wait CLOCK SOURCE_SHA LEASE_FILE_SHA256 COUNT`
在拥有 port-forward 的同一 shell 中进行一次新的受保护栈采集，随后调用
`expired-lease-wait-frames.jq` 分类。COUNT 只能为 1（待响应候选）或
0（降级后无候选）；CLOCK 为 `before-fault` 或已有原始故障纳秒时钟。
分类器必须纳入准入时冻结的 tools.sha256，分类前后复核捕获文件与工具。
故障时钟约束涵盖分类、哈希与最终标记，不能重置或另开 30 秒。

成功后 `stack_wait` 指向独立的 `expired-wait.*` 证据目录，包括输入绑定、
原始 capture 路径、候选帧、清单及明确不代表故障成功的完成标记。
每次调用先清空该变量，避免失败时误取上次证据。原始栈和其采集清单
保持不变。源码绑定只允许已审查的精确 SHA/文件哈希，不代替镜像 CI
准入；候选帧不携带租约身份，仍须由原探针监督器、当前 term、排他认领
及完整故障驱动共同验证。该函数本身不启动原续租请求或注入网络故障。

该封装不改变匿名 mTLS 拒绝可能终止其 port-forward 的事实，也不允许
故障期 rearm。需要激活前与降级后两次故障期栈采集时，必须在原故障
时钟开始前准备独立的拥有者会话/独占端口，纳入统一进程监督和回收；
不能假设同一个匿名通道可供第二次采集，或为第二次采集重开预算。

`protected-wait-worker.sh POD SOURCE_SHA LEASE_FILE_SHA256 COUNT RECEIPT_DIR`
提供上述会话的独立进程入口，协议兼容 `metricsworker.WithPreparedFault`。
它在准备好通道后只输出 `FAULT_READY`，随后读取一次原始故障时钟，执行
一次绑定采集，输出 `FAULT_DONE\tCLOCK` 并退出回收通道；它不执行故障
注入，不能作为完整故障驱动使用。默认端口为 18588/18589，第二个会话
必须通过独立环境分配不冲突的端口，并在原故障时钟开始前完成准备。

调用方须预建 owner 的直接子目录 `stack-worker.XXXXXXXX`（8 位字母数字），
目录归当前用户所有、权限 0700 且为空。worker 用 started 子目录防止复用，
自身脚本及分类器均须在准入时冻结进 tools.sha256。其他环境与栈会话相同，
没有隐式凭据。成功回执包含 capture-path、classification-path、origin-ns
及退出时写入的 exit-code。缺失回执不是成功；强制终止时可能没有退出回执，
必须以监督器的回收结果及独立清理审计为准。

激活前接入方式是预先用 WithPreparedFault 准备 count=1 的 worker，在
OriginalProbe.Pending 的观察回调中调用它提供的 capture(ctx, origin)，
然后验证同一预分配目录的退出及分类证据。count=0 的降级后观察须预先
准备另一 worker。还必须补齐实际当前 term、Pod 身份、独立认领准入及
剩余故障门限；当前只有真实脚本+模拟 Kubernetes 输入的组合测试，尚无
完整真实集群驱动闭环。测试覆盖成功、候选数错误、绑定缺失、探针失败
和准备完成后控制器拒绝；它不把合成栈视作真实租约阻塞证明。

实际 worker 被监督器 join 后，可用 `leasefault.LoadWaitReceipt` 将退出
回执绑定到独立提供的原时钟、源码/文件哈希和候选数。它只允许 owner
下固定前缀的私有兄弟目录，限长读取普通文件，拒绝符号链接/FIFO，
按固定文件集合验证分类与原始捕获两层 SHA256 清单，绝不按清单提供的
任意路径读取。它还复查完成标记、分类输入及读取前后的 worker 回执。

该读取器不重新运行源码分类器、不证明 worker 已退出或镜像已获准，也
不把哈希当作来源认证。必须先运行并 join 经准入固定工具的实际 worker，
保持目录排他控制，另做实时身份/term 检查，并在原截止时间内完成读取
及最终复核；离线读取器自身不启动新预算。实际脚本测试已接入它，并
覆盖时钟/候选数不匹配及退出回执、路径、原始栈、Pod 快照、分类输入、
候选帧、清单、完成标记被修改后的拒绝。

`leasefault.WithWaitObservation` 将上述步骤连接为可直接调用的观察入口：
启动前准入 → 准备实际 worker → 控制器调用一次 observe(ctx, origin)
→ 发送原时钟并 join → 再准入 → LoadWaitReceipt → 留存 → 最终预算复核。
observe 可直接放入 OriginalProbe.Pending 的观察回调，不再由调用方
自行拼接退出码和离线回执。它不注入故障，不创建新的响应或预算。

配置中的 Admit 必须绑定具体命令及其参数、预分配目录、工具/镜像源码
准入和当前集群认领/Pod/term；测试中的空实现仅用于模拟输入。Retain
必须持久化成功或回执校验失败的结果。控制器必须串行、同步调用 observe
且遵守 context；观察失败不能重试或被吞掉，第二次调用也会使整个入口
失败。回执校验和留存都在原截止时间内复核，不能使用恢复预算补做。
脚本/进程错误仍由私有 stderr 与监督器保留，不会伪造成功回执。

`WithOriginalObservation` 进一步组合一个原探针和两个独立的等待栈
worker：先准备 count=1 / count=0 的会话，再启动一次原探针并等到其
两条请求事件。配置要求两个 worker 目录不同、源码绑定一致，具体
命令/端口/镜像/当前身份仍必须由 Admit 核验。

控制器必须按顺序调用 `ObservedOriginal.Pending(ctx, origin)`、执行
独立故障/丢包/继任者观察、再调用 `Finish(ctx, origin, successorTerm)`。
Pending 把待响应日志与第一份栈证据连接；Finish 使用第二份无候选栈、
同一探针的实际退出和完整响应校验，最后才允许 Evidence 返回副本。
继任 term 必须来自独立观察，不能取自被测响应。重复操作、换时钟、
错误顺序、留存失败或忽略内部错误均不能成为成功；函数返回前统一
回收这些受管进程，逃逸后代仍需独立 Join 审计。

组合测试使用真实 Bash worker 和模拟集群/原响应，覆盖完整顺序与
完成阶段偷偷更换原时钟的拒绝；不是实际故障验收。

RunFaultLifecycle 现可通过 Observation 选择这个原生组合路径。它与
外部 Fault 命令及 OriginalPending/OriginalEvidence 回调互斥，启动前
将租约、集群和初始成员身份绑定到协议准备计划，并检查三个子进程
命令和日志。准备协议后才启动观察组件；父进程继续负责唯一的策略
激活，随后调用只读 ObserveFault 获取独立的丢包/继任 term 证据，再
执行原生完成和最终 lease/key 读取。观察回调均增加实际认领的前后
